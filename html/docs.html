1✦Что такое B+What is B+

Превращает ваш код прямо в готовую программу для Windows — без внешних компиляторов, ассемблеров и линкеров. Весь конвейер от исходника до PE-файла делает один инструмент: bpc.

Turns your code directly into a ready Windows program — no external compilers, assemblers or linkers. One tool, bpc, runs the whole pipeline from source to the PE file.

PLAN — состоянияPLAN — states

Описание логики как машины состояний: меню игры, состояния персонажа, сетевые протоколы, обработчики событий.

Logic as a state machine: game menus, character states, network protocols, event handlers.

METAL — функцииMETAL — functions

Процедурный код: функции, переменные, структуры, ветвления, циклы, арифметика, print.

Procedural code: functions, variables, structs, control flow, arithmetic, print.

Из коробкиOut of the box

Свой x64-бэкенд, SSA, оптимизации, встроенный рантайм и линковка в PE — без зависимостей.

Own x64 backend, SSA, optimizations, embedded runtime and PE linking — zero dependencies.

Самый первый шаг: hello

Very first step: hello

Every program starts from the fn main() entry point.

print принимает числа, строки в кавычках и f64. Файл сохраняется как hello.b+.

print takes numbers, quoted strings and f64. Save the file as hello.b+.

fn main() {

2

Переменные

Variables

Записываются как var имя: тип = значение, потом подчиняются присваиванию.

Written as var name: type = value, then set with =.

Тип можно указать явно или вывести из значения. Голое var y; = переменная i64 на ноль. Для дробных чисел нужна аннотация f64.

Type can be explicit or inferred from the value. A bare var y; is an i64 zero variable. Floats need the f64 annotation.

var.b+
fn main() {
    var x: i64 = 42;   // тип + значение// type + value
    var y;            // без типа → i64 (0)// no type → i64 (0)
    var z = 10;        // вывод типа// type inference
    x = x + 1;       // перезапись// overwrite
    print(x);           // 43
}
3

Вычисления и print

Arithmetic and print

Все обычные операторы работают: + − * / %, сравнения, скобки.

All usual operators work: + − * / %, comparisons, parentheses.

Приоритет как в математике: сначала умножение/деление, потом сложение. В скобках — в первую очередь.

Precedence is like math: multiply/divide first, then addition. Parentheses win.

arith.b+
fn main() {
    print(2 + 3 * 4);   // 14
    print((2 + 3) * 4); // 20
    print(10 % 3);        // 1
    print(5 > 3);          // 1 (true)
}

💡 Строки «склеиваются» через +, если хоть одна часть — строка: "год " + 2026.

💡 Strings concatenate with + when either side is a string: "year " + 2026.

4

Условия: if / else

Conditions: if / else

Ветвление для принятия решений. Условием может быть любое сравнение.

Branching to make decisions. Any comparison works as the condition.

if.b+
fn main() {
    var x: i64 = 7;
    if x > 5 {
        print("больше");
    } else {
        print("меньше");
    }
    // скобки у условия тоже допустимы:// parenthesized conditions are fine too:
    if (x == 7) { print("семь"); }
}

💡 Поддерживаются else if, а также == != > < >= <= && || !.

💡 Supports else if, plus == != > < >= <= && || !.

5

Циклы: while и for

Loops: while and for

Повторение кода, пока верно условие.

Repeat code while the condition holds.

while.b+
fn main() {
    var i: i64 = 0;
    while i < 3 {
        print(i);
        i = i + 1;
    }
    // for — C-стиль: init; условие; шаг// for — C-style: init; condition; step
    for j = 0; j < 3; j = j + 1 {
        print(10 + j);
    }
}

💡 Форма for i in 0..10 недоступна — только C-стиль. Составные присваивания i += 1 в этой версии нет, пишите i = i + 1.

💡 The for i in 0..10 form is not available — C-style only. Compound assignment i += 1 is not in this version; write i = i + 1.

6

Функции и рекурсия

Functions and recursion

Код можно выносить в функции с параметрами и возвратом через return.

Code can be factored into functions with parameters and a return.

fib.b+
fn add(a: i64, b: i64) -> i64 {
    return a + b;
}

fn fib(n: i64) -> i64 {
    if n < 2 { return n; }
    return fib(n - 1) + fib(n - 2);
}

fn main() {
    print(add(3, 4));  // 7
    print(fib(10));   // 55
}

💡 Возврат — только явный return. Функция видна и до её объявления, рекурсия работает.

💡 Return is explicit only. A function is visible even before its declaration; recursion works.

7

Структуры

Structs

Сгруппируйте поля в один тип данных.

Group fields into one data type.

struct.b+
struct Point {
    x: i64,
    y: i64,
}

fn main() {
    var p: Point;
    p.x = 10;
    p.y = 20;
    print(p.x);   // 10
    print((p.x + p.y)); // 30
}

💡 Литералы вида Point { x: 10 } не поддерживаются — создавайте переменную и заполняйте поля по одному.

💡 Struct literals like Point { x: 10 } are not supported — create a variable and set fields one by one.

8

PLAN — состояния

PLAN — states

Программа как машина состояний: опишите состояния и переходы по событиям.

A program as a state machine: describe states and event-driven transitions.

on событие -> Состояние — переход по событию. on open [key == 1] — переход только при верном условии. always -> Состояние — сразу без события. Код на входе в состояние — в entry.

on event -> State — transition on an event. on open [key == 1] — only when the condition holds. always -> State — immediately, no event. Code on state enter goes in entry.

door.b+ — PLAN
state Locked {
    on open [key == 1] -> Opened
    entry { print("locked") }
}

state Opened {
    on close -> Locked
    entry { print("opened") }
}

fn main() {}
живой граф состоянийlive state graph

💡 Для запуска PLAN-модуля нужна функция fn main() — диспетчер состояний подключается из рантайма.

💡 Running a PLAN module needs fn main() — the state dispatcher is wired from the runtime.

9?FAQ

Почему примеры в README в блоке ```rust?Why are README examples in ```rust blocks?+
Это язык B+, а не Rust. Тег rust просто включает подсветку синтаксиса на GitHub — фактического отношения к Rust нет.
That's B+, not Rust. The rust tag only enables GitHub syntax highlighting — it has nothing to do with Rust.
Сколько слоёв проходит программа?How many layers does a program go through?+
Parser → AST → HIR → THIR → BIR (SSA) → оптимизации → MIR → верификация → x64 backend → PE/COFF.
Parser → AST → HIR → THIR → BIR (SSA) → optimizations → MIR → verification → x64 backend → PE/COFF.
Нужен ли LLVM или линкер?Is LLVM or a linker required?+
Нет. Кодогенератор x64 и упаковка PE написаны с нуля. Для lock-линковки опционально используется lld-link.
No. The x64 codegen and PE packaging are written from scratch. lld-link is used optionally for linking objects.
Где хранится код?Where is the code hosted?+
GitHub — основной репозиторий. GitLab, GitVerse и GitFlic — автоматические зеркала.
GitHub is the primary repo. GitLab, GitVerse and GitFlic are automatic mirrors.
Что делать с ошибкой UndefinedVReg / конфликтом регистров?What about UndefinedVReg / register conflicts?+
Это известная область бэкенда (регистровый аллокатор/верификатор) — активно дорабатывается. Используйте bpc check для ранней диагностики слоёв.
A known backend area (register allocator/verifier) under active work. Use bpc check for early layer diagnostics.
